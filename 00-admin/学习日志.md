\*\*今天真正理解的事（明天只需记这三句）\*\*

1\. input() 永远返回文字 → 想要数必须 int() 或 float()

2\. 钱用 float，个数用 int

3\. 看到引号就是文字；不报错 ≠ 算对了



其他学到的

\- 程序分三段：进（input）/ 算（无 input）/ 出（print）；换数据只改"进"那一段

\- int 是"砍掉小数"（int(9.99) → 9），round 才是四舍五入（round(9.99) → 10）

\- "7" + "7" → '77'（文字拼接）；"7" \* 3 → '777'（重复）；结果带引号就说明是文字

\- 运算符号：/ 给小数（10/4 → 2.5）｜// 只留整数（10//4 → 2）｜% 取余（10%3 → 1）

\- round(x, 2) 只改显示，不改盒子里的值；gross 里还是 224.24999999999997

\- 浮点误差来自二进制存不准，钱最后都要 round

\- 钱该用 int 吗？—— 该，但要存"分"不是"元"：int 存元会把 124.5 吞成 124

\- 报错五种：SyntaxError（语法）/ NameError（名字没定义）/ TypeError（类型不对）/ ValueError（值不对）/ IndentationError（缩进不对）

## 2026-11-05  D5  ·  list + for 循环

### 今天做了什么
- REPL 练 list：sales[0] / sales[6] / sales[-1] / sales[7] → IndexError
- forloop.py：for 遍历列表打印 7 天 + len()
- week2.py：累加器算总营业 3428、平均 489.71、max 720、min 325
- 故意把 total = 0 缩进到循环里 → 总营业变成 413（只算最后一天）

### 今天真正理解的事
- 索引从 0 开始，最后一个编号 = len - 1，差一位不会报错只会悄悄算错
- for 不需要我管"挪步"，所以不会死循环；while 需要我管，所以会
- 累加器必须在循环外面（存钱罐在循环外面买一次）
- 413 看起来"像真的"（59元/天），这就是 bug 最危险的地方
- enumerate 同时给编号和元素；i 从 0 开始所以显示要 i+1
